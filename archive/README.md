### Зачем понадобился C++-датчик

Источник — сессия OpenCode «Greeting», 25.10.2026 (Mercury 3). Автор: «Можешь всё что на пайтане написанно переписать на с++?» Ответ модели про датчик: «уйдёт зависимость от torch (~1–2 ГБ в RAM), станет мгновенно. Это реально оправдано». Автор: «Делай, только чтобы без ошибок». Из трёх предложенных переносов сделаны два (units, probe); perception «оставлен на Python» (журнал, 25–26.10).

Почему не пригодился (по коду): с 24.10 совет v3.9 берёт оценку датчика из сервера мозга (`"probe": true`, комментарий в `src/council/council.py`), где она уже считается на C++ без torch. `probe.dll` нужен вектор скрытого состояния слоя 16, а сервер его наружу не отдаёт, — так что DLL годится только для пересчёта сохранённых состояний в опытах.
